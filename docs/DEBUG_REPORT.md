## 3. Data-Model Audit (Forms/Tables/Relations)

Every SQLAlchemy model in `backend/app/models.py` and every Pydantic schema in
`backend/app/schemas.py` was cross-checked field-by-field against the corresponding frontend
form (`FieldDef[]` arrays) and table columns. Scope covered:

- Element Administration (`Element`, `InspectionReport`, `InspectionHalfshellGrid`)
- Anodes / Cathodes / Membranes + their Maintenance / Recoating / Coating-Check sub-tables

- Remarks
- Settings / plant configuration (Electrolyzers, Sub-Plants, Full Plants, Rectifiers,
  Transformers, Arrangements, Reserve Positions, Correction Factors, Electrode Areas, Voltage
  Distribution Classes, Group Definitions, Inspection Reasons/Findings, Cell Components)

### 3.2 Explicitly reviewed and confirmed correct (no action needed)

- All primary entity forms (`Element`, `Anode`, `Cathode`, `Membrane`, `Shutdown`,
  `ElectrolyzerNormalization`, `VoltageReading`, `CurrentEfficiencyEntry`, `Remark`, all
  lookup/settings tables) already expose every editable backend field.
- Read-only computed fields (`Element.status`, `Element.computed_dol_days`,
  `CellComponent.recommended_spares`, `CellComponent.calculated_spares`,
  `Shutdown.duration_hours`) are correctly displayed but not exposed as editable inputs, which
  is the intended behavior (they are derived server-side).
- `InspectionReason.language_id`, `InspectionFinding.language_id`, and
  `ShutdownCause.language_id` are legacy multi-language row-linking columns inherited from the
  original Access schema. They are not exposed as editable fields in the single-language admin
  UI; this is a deliberate simplification (documented here rather than silently omitted) since
  changing it would require redesigning those lookup tables around multiple language rows per
  concept, which is out of scope for this pass.
- `AnodeMaintenance`/`CathodeMaintenance`/`MembraneMaintenance`,
  `AnodeRecoating`/`CathodeRecoating`, and `AnodeCoatingCheck`/`CathodeCoatingCheck` were
  compared pairwise — the anode/cathode variants intentionally differ in a few fields (e.g.
  anodes have `baffle_plate`/`downcomer`/`coating_nr`/`recoating_number`/`dol_days` that
  cathodes do not), and the frontend forms correctly mirror those differences rather than being
  copy-paste identical.
- All backend routers registered in `backend/app/main.py` have a corresponding frontend page or
  UI element consuming them; no orphaned backend endpoint or orphaned frontend page was found.
- `statisticsApi`, `reportsApi`, `searchApi`, and `dataTransferApi` endpoint calls in
  `frontend/src/lib/endpoints.ts` all match their backend router paths exactly.

## 6. Known Limitations / Deliberately Out of Scope

- `language_id` columns on `InspectionReason`, `InspectionFinding`, and `ShutdownCause` are not
  independently editable per language in the UI (see §3.2). This mirrors the original system's
  data model but does not currently offer a UI to manage multiple language variants of the same
  reason/finding/cause row.
- The default admin account and JWT secret ship with development placeholder values
  (`backend/app/config.py`); **these must be changed before production deployment** — this is
  called out explicitly in `SECURITY.md` §6–7 and in the README's "First login" section.
- The Software has no automated end-to-end (browser) test suite; verification in this pass was
  performed via static analysis (type-check/lint/build), a translation-coverage script, and
  direct API smoke tests. Manual UI verification in the browser is still recommended before
  each release, particularly for RTL (Persian) layout on new pages.
